# Sistema de Gestão de Metas

Aplicação web para cadastro de usuários, acompanhamento de metas e visualização de dashboards por perfil. O frontend usa React + Vite e a autenticação e o banco de dados usam Supabase.

## 1. Pré-requisitos

- Node.js 20 ou superior
- Uma conta no [GitHub](https://github.com/)
- Uma conta no [Supabase](https://supabase.com/)
- Uma conta no [Vercel](https://vercel.com/)

## 2. Rodar localmente

```bash
npm install
npm run dev
```

Abra `http://localhost:3000` no navegador. Sem as variáveis do Supabase, o sistema abre automaticamente em modo demonstração.

Para verificar os tipos antes de publicar:

```bash
npm run lint
npm run build
```

## 3. Criar o projeto no Supabase

1. Acesse o painel do Supabase e clique em **New project**.
2. Escolha a organização, informe um nome e defina uma senha forte para o banco.
3. Aguarde o projeto ficar pronto.
4. Abra **Project Settings > API** e copie:
    - **Project URL**
    - **anon / public key**
    - **service_role key** (somente para o servidor; nunca publique esta chave no frontend)
5. Abra **SQL Editor > New query**, cole o SQL abaixo e clique em **Run**.

O cadastro e os dashboards atuais usam as tabelas `profiles` e `activity_logs`. O proprietário pode criar acessos individuais ou importar uma planilha XLSX pelo painel. A planilha deve ter uma linha de cabeçalho com:

| matricula | senha | tipo_de_conta | nome | whatsapp |
| --- | --- | --- | --- | --- |
| 1001 | Senha@123 | agente | Ana Souza | 11999999999 |
| 1002 | Senha@123 | coordenador | Carlos Lima | 11999999998 |
| 1003 | Senha@123 | gerente | Maria Silva | 11999999997 |
| 1004 | Senha@123 | diretor | Joao Santos | 11999999996 |

Os tipos aceitos são `agente`, `coordenador`, `gerente`, `diretor`, `administrador`, `criador` e também os códigos internos `AGENT`, `COORDINATOR`, `GN`, `BOARD`, `ADMIN` e `OWNER`.

```sql
create table if not exists public.profiles (
   id uuid primary key references auth.users(id) on delete cascade,
   name text not null,
   enrollment text not null unique,
   whatsapp text,
   role text not null default 'AGENT' check (role in ('OWNER', 'ADMIN', 'BOARD', 'GN', 'CR', 'COORDINATOR', 'AGENT')),
   unit_id text,
   polo_id text,
   is_active boolean not null default true,
   created_at timestamptz not null default now()
);

create table if not exists public.activity_logs (
   id bigint generated by default as identity primary key,
   user_id uuid references auth.users(id) on delete set null,
   user_name text not null,
   action text not null,
   details text,
   created_at timestamptz not null default now()
);

alter table public.profiles enable row level security;
alter table public.activity_logs enable row level security;

create policy "Usuários podem consultar o próprio perfil"
   on public.profiles for select
   to authenticated
   using (id = auth.uid());

create policy "Usuários podem criar o próprio perfil"
   on public.profiles for insert
   to authenticated
   with check (id = auth.uid());

create policy "Usuários autenticados podem registrar atividades"
   on public.activity_logs for insert
   to authenticated
   with check (user_id = auth.uid());

create policy "Usuários autenticados podem consultar atividades"
   on public.activity_logs for select
   to authenticated
   using (true);
```

Em **Authentication > Providers > Email**, mantenha o provedor de e-mail habilitado. O sistema converte a matrícula cadastrada em um e-mail interno no formato `matricula@metas.com`; portanto, o usuário entra com a matrícula e a senha definida no cadastro.

Depois do primeiro cadastro, altere manualmente o campo `role` do usuário administrador em **Table Editor > profiles**, por exemplo:

```sql
update public.profiles
set role = 'OWNER'
where enrollment = 'SUA_MATRICULA';
```

## 4. Configurar o arquivo `.env`

Na raiz do projeto, crie um arquivo chamado `.env` (não use `.env.example` para guardar credenciais). Use este modelo:

```env
# Usada pelo frontend Vite
VITE_SUPABASE_URL=https://SEU-PROJETO.supabase.co
VITE_SUPABASE_ANON_KEY=SUA_CHAVE_ANON_PUBLICA

# Usadas pelo servidor Express em server.ts
SUPABASE_URL=https://SEU-PROJETO.supabase.co
SUPABASE_SERVICE_ROLE_KEY=SUA_CHAVE_SERVICE_ROLE

# Criador e gerenciador geral inicial
OWNER_LOGIN=digoslab
OWNER_PASSWORD=DEFINA_A_SENHA_LOCALMENTE

# Opcional, caso algum recurso de IA seja habilitado
GEMINI_API_KEY=SUA_CHAVE_GEMINI

# Opcional
APP_URL=http://localhost:3000
```

Regras importantes:

- `VITE_SUPABASE_ANON_KEY` pode ser usada no frontend, desde que as políticas RLS estejam configuradas.
- Nunca coloque `SUPABASE_SERVICE_ROLE_KEY` em código frontend, commit do GitHub ou variável `VITE_`.
- `OWNER_PASSWORD` também é segredo: use localmente a senha desejada e não publique esse valor no GitHub ou na Vercel.
- O `.gitignore` já bloqueia arquivos `.env`; mantenha apenas valores fictícios no `.env.example`.
- Após alterar variáveis, reinicie o servidor de desenvolvimento.

Ao iniciar o servidor com `OWNER_LOGIN` e `OWNER_PASSWORD` configurados, ele cria ou atualiza automaticamente o usuário proprietário. Para o acesso solicitado, use `digoslab` como login e defina no `.env` a senha escolhida por você. O servidor converte o login em `digoslab@metas.com` internamente para o Supabase Auth.

## 5. Publicar no GitHub

No terminal, dentro da pasta do projeto:

```bash
git init
git add .
git commit -m "feat: inicio do sistema de gestao de metas"
git branch -M main
git remote add origin https://github.com/rrodshek-design/gestao-metas-inec.git
git push -u origin main
```

Antes do `git add .`, confirme que o arquivo `.env` não está sendo enviado:

```bash
git status
```

Caso o projeto já tenha um repositório remoto chamado `origin`, use:

```bash
git remote set-url origin https://github.com/rrodshek-design/gestao-metas-inec.git
```

O repositório usado neste projeto é: [github.com/rrodshek-design/gestao-metas-inec](https://github.com/rrodshek-design/gestao-metas-inec).

## 6. Publicar o frontend na Vercel

1. Entre na Vercel e clique em **Add New > Project**.
2. Importe o repositório do GitHub.
3. Confira as configurações:
    - **Framework Preset:** `Vite`
    - **Build Command:** `npm run build`
    - **Output Directory:** `dist`
    - **Install Command:** `npm install`
4. Em **Environment Variables**, cadastre pelo menos:
    - `VITE_SUPABASE_URL`
    - `VITE_SUPABASE_ANON_KEY`
5. Clique em **Deploy**.
6. Depois da publicação, copie o domínio da Vercel e cadastre-o no Supabase em **Authentication > URL Configuration**:
    - **Site URL:** `https://SEU-PROJETO.vercel.app`
    - **Redirect URLs:** `https://SEU-PROJETO.vercel.app/**`

### Limitação das rotas administrativas

O arquivo `server.ts` executa um servidor Express local na porta 3000 e contém as rotas `/api/admin/block-user` e `/api/admin/logs`. A configuração acima publica o frontend Vite como site estático; essas rotas Express não são iniciadas automaticamente pela Vercel.

Assim, o login, cadastro e consultas diretas ao Supabase funcionam na Vercel, mas as ações administrativas que dependem de `/api/admin/*` precisam de uma destas opções:

1. Migrar essas rotas para Vercel Functions;
2. Hospedar o servidor `server.ts` em Render, Railway ou outro serviço Node e configurar o frontend para chamar a URL desse servidor.

Para publicar somente a versão demonstrativa ou o frontend com Supabase, não é necessário configurar `SUPABASE_SERVICE_ROLE_KEY` na Vercel. Se o servidor Express for hospedado separadamente, configure nele `SUPABASE_URL` e `SUPABASE_SERVICE_ROLE_KEY` como variáveis privadas.

Depois de alterar o código:

```bash
npm run lint
npm run build
git add .
git commit -m "descreva a alteracao"

```

A Vercel fará um novo deploy automaticamente a cada push na branch conectada, normalmente `main`.
